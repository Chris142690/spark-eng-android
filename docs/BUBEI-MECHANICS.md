## 一、一个词要过几关

不是「学一遍」，是**连续答对 4 次**才算学完。中途错一次，之前答对的全清零。

页面原文（第 10 轮抓到）：

```
答对次数已清零，还需连续答对 4 次
```

学完的页面原文：

```
本词学习完成，已进入复习队列
```

### 四关的顺序

| 关 | 题型 | 界面 | 判分 |
|---|---|---|---|
| 1 | 四选一（看词选义） | 大字单词 + 音标 + 4 个中文释义 | 点对才进 |
| 2 | 释义页 | 音节切点 + 音标 + 多词性 + 例句 + 搭配 | 读完点「下一词」 |
| 3 | 语境判断（带提示） | 纯英文例句 + 「提示一下」+ 认识/不认识 | 点「认识」 |
| 4 | **最后一关（无提示）** | `本词最后一关😀：请在无提示的情况下判断` | 点「认识」→ 完成 |

第 4 关是关键：**前面给过例句、给过提示，最后这一关什么都不给，只问你还认不认识。**

## 二、连击机制 = 「高利贷」的真正来源

- 不是「累计答对 4 次」，是**连续**答对 4 次
- 错一次 → `答对次数已清零` → 从 1 开始
- 没学完的词**留在当天队列反复出现**

实测 `midnight` 出现了 **12 次**（我脚本在四选一时匹配失败反复点「看答案」），`import` / `pledge` / `contribute` 各 6 次。

**这就是用户说的「一天不背第二天就要复习几百个，像欠了高利贷」的机制根源**：它不允许「今天先这样」，没连对就不放你走。

## 三、干扰项是形近词，不是随机

实测样本（括号内是干扰词原形）：

| 目标词 | 四个选项 |
|---|---|
| `forum` | 论坛 ✅ / 公式分子式(formula) / 四十(forty) / 缔造伪造(forge) |
| `tone` | 语气 ✅ / 舌头(tongue) / 石头(stone) / 骨头(bone) |
| `range` | 一系列范围 ✅ / 暴怒(rage) / 安排(arrange) / 级别军衔(rank) |
| `capture` | 抓住俘虏 ✅ / 首都资本(capital) / 胶囊航天舱(capsule) / 船长上尉(captain) |
| `skill·ed` | 有技术的 ✅ / 愚蠢的(silly) / 长柄平底煎锅(skillet) / 盾牌(shield) |
| `waste` | 浪费 ✅ / 意大利面食(pasta) / 更快的(faster) / 命运宿命(fate) |
| `starve` | (使)挨饿 ✅ / 努力奋斗(strive) / 盯着看凝视(stare) / 惊吓使恐惧(startle) |
| `downtown` | 在市中心 ✅ / 到…上(down) / 洋葱(onion) / 捐赠物(donation) |
| `conceal` | 掩盖隐藏 ✅ / 麦片(cereal) / 承认属实(concede) / 建议辩护(counsel) |

**规律：按拼写相似度选，共享前缀/后缀/元音骨架。**
`forum` 三兄弟全带 `for`；`capture` 三兄弟全带 `cap`；`starve` 三兄弟全带 `star`。

它不拿「苹果」当干扰项——它精确地打在你**容易混淆的那个边界**上。选错不是粗心，是它找到了你的混淆。

**选项位置每次进入随机重排**，不能靠位置记忆。

## 四、答错时的反馈：当场并列英文原词

我在 `conceal` 故意选「麦片」，界面立刻变：

```
conceal   vt. 掩盖，隐藏      ← 正确项补上英文
cereal    n. 麦片…            ← 误选项也补上英文
```

其余两项不变，底部按钮 `看答案` → `继续`。

**这是「你以为的那个词」和「正确的词」并排摆出来**，不是只告诉你答案。

## 五、释义页的信息结构（信息密度很高）

以 `claim` 为例：

```
claim                          ← 词形（无音节点时）
/kleɪm/                        ← 音标
vt.  声称；认领；获得；夺去(生命)   ← 按词性分列
vt.vi. 索要，索取
n.   声称；所有权；要求，索赔

She claims to be the princess.  ← 英文例句
她声称自己是公主。                ← 中文翻译

claim your baggage   行李认领      ← 搭配，3–6 条
claim compensation   索赔
deny a claim         否认说法
make a claim         提出索赔
claim to do          声称要做某事
a claim on sth       对…的所有权
```

### 词形上直接打音节切点

| 原词 | 显示 |
|---|---|
| conceal | `con·ceal` |
| install | `in·stall` |
| effective | `ef·fect·ive` |
| midnight | `mid·night` |
| fantastic | `fan·tas·tic` |
| contribute | `con·tri·bute` |
| downtown | `down·town` |

不是「词 + 音标」，是**在词上断开**。你读的时候自然就分节了。

### 四个 tab（按词性有无动态出现）

`词组搭配`(190,2282) / `派生`(391,2282) / `词根`(553,2282) / `近义`(715,2282)

- **词根**：`前缀 con- (com-) = 一起；全；加强语气` / `词根 ceal = 隐藏`
- **派生**：`conceal v. 掩盖隐藏`[四级] / `concealed adj. 隐蔽的`[四级]
- **近义**：`conceal / hide ...`（文本被截断，UI 缺陷）
- `claim` 没有「词根」tab（因为它不可拆）

### 底部两个按钮

`下一词`(630,2576) / **`记错了`(931,2576)** —— 后者是自我修正入口，点了会把它重排回队列。

## 七、时间成本（实测）

- 我的脚本跑 5 个词（2/10 → 7/10）用了约 **13 分钟**，但其中大量是 `uiautomator dump` 的延迟（每步 1–2 秒）
- 真人速度取决于认识程度：全会的走完 4 关约 20–30 秒/词；不认识的会反复循环
- **10 词 × 4 关 = 至少 40 次交互**

## 八、对 AURORA 的结论

### 该抄（按成本从低到高）

| 设计 | 成本 | 说明 |
|---|---|---|
| **答错并列英文对比** | 低 | 判错时把用户选的词也显示出来，当场对比 |
| **音节切点** | 低 | 词表加 `con·ceal` 字段，显示时用 |
| **「最后一关无提示」** | 低 | 学完前加一屏，什么都不给，只问认不认识 |
| 形近词干扰 | 中 | 需要形近词库（可按编辑距离从 1,208 词里生成） |
| 搭配 3–6 条 | 中 | ECDICT 无搭配字段，需另抓或手工补高频词 |
| 单词＋实景图 | 高 | 1,208 张配图做不了 |

### 不能抄

**「不连对 4 次不许走」**。这是它压力的全部来源，也是用户明确否掉的东西。

AURORA 的懒筛 + FSRS 核心是「今天没学会，明天再来」，不是「今天不学会不许走」。

### 正确的组合

```
抄它的即时纠错（答错对比、形近干扰、最后一关自我确认）
丢掉它的当天下课机制（连击清零、不出队循环）
交给 FSRS 排到明天
```

效果：得到「每个词都被认真对待」的感觉，不会得到「高利贷」的感觉。
